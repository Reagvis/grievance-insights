## Operator-facing scope

The signed-in AWS pilot's **Assistant → Ask** tab uses Qwen3-32B via Amazon Bedrock. The operator can ask about an opened complaint, its originating uploaded file, or any other ready uploaded file from the Ask scope selector, and request free-form summaries, key points, emails, government file notings, draft letters, translations and suggested actions. Follow-up messages are sent in the same request as bounded in-memory history. Source files are never modified. Task 23A (pending independent review and separate deployment approval) removes the Assistant mode toggle and user-visible model branding. The Assistant opens directly into document chat; existing analysis jobs, APIs, dashboard analysis workspace and model configuration remain intact.

- Document context comes from the authenticated private S3 dataset index. The browser sends an uploaded-file UUID, an optional original case ID and index, plus the operator's messages; it never supplies untrusted source text to authorize.
- Server independently checks the existing hashed session, same-origin POST, ready dataset and ownership before reading sources or invoking Qwen.
- API: `POST /api/datasets/{id}/chat` wired to the existing analysis API Lambda. Qwen model and region match existing analysis (`qwen.qwen3-32b-v1:0`, `ap-south-1`). The existing Lambda role already has bounded dataset GetObject and Bedrock InvokeModel permissions. One explicit new HTTP API route is required; no eOffice route is enabled.
- Response: `{answer, citations, model}`. A citation is emitted only when one original record was supplied; for multi-record files the MVP deliberately does not assert that all supplied records were actually used. The browser resolves original case IDs to the merged All Complaints IDs before making them clickable.
- Current MVP bounds: 16 KiB request body, 12 chat messages, 4,000 characters/message, 24 KB source JSON, 32 KB combined system/source/history prompt, 40 full-file records, 1,500 output tokens and an 18-second Bedrock deadline. Oversized material is **rejected, not silently truncated**. A specific complaint can still be selected from a 2,000-record file with an authenticated record index.
- Model-generated notings, decisions, suggested remedies and draft correspondence require operator review. The model must not claim a department response means verified resolution.
- No chat history persisted in S3/DynamoDB or browser storage. The pilot chat store is scoped to a mounted dataset/record identity. Changing the selected file or complaint (including fallback when a file disappears), closing the panel, or signing out discards the entire conversation and draft; late callbacks from an invalidated request are ignored. The normal browser supplies only the current scope's bounded history. Standard Lambda/service logs must not contain source text or prompts.

## Task 23A scope and security notes (not yet deployed)

- The existing single model call explicitly distinguishes document-related requests from unrelated trivia, news and arbitrary creative tasks; document-based translations, formal rewrites and drafts remain valid. A model reply consisting of `[[OUT_OF_SCOPE]]` is mapped by the server to a fixed, neutral redirection without citations. No external retrieval, new model, additional inference call or API contract change is introduced.
- Semantic relevance is **not** a deterministic security guarantee. The mocked model exercises the refusal protocol, not real Qwen accuracy; false acceptance/refusal and prompt injection remain possible. Client-supplied conversation text is untrusted, not evidence or a mechanism for authorizing another document. The API is stateless and cannot prove the provenance of manually fabricated history. Real-model evaluation requires separate approval.
- The original session cookie, origin and owner checks remain before private reads. Dataset identity/status and active session are rechecked before and after model execution; deletion or expiry during preparation suppresses inference, and changes during inference suppress the answer. These checks narrow but cannot eliminate distributed races or cancel inference already dispatched. No infrastructure, persistence, dependency or package configuration changes.
- Verification: focused mocked backend/client/markup tests and synthetic browser interaction harness; run locally with Node 22 and Chromium. No paid inference or production rollout is part of this task. Historical rollout steps above describe the earlier MVP, not authorization to deploy this PR.

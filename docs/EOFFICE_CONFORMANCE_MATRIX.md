## Task 22A code changes

1. `backend/eoffice/schema.ts` — missing, empty or whitespace-only nullable optional extraction strings normalize to `null`. Non-nullable required fields still fail with 422; wrong-type model output remains 502. Direct basis: PDF §2.3, p.3.
2. `backend/eoffice/core.ts` — invalid source `page_number` (≤0, fractional, nonfinite) is rejected before generating external JSON. Direct basis: PDF §3.4, pp.5–6.
3. `backend/eoffice/contract.test.ts` — isolated mocked tests cover all four public envelopes, required and nullable extraction fields, UUID echo, standard errors, source reference validation and fail-closed production handler. Four additional representative request/response fixtures are adapted from **the actual PDF examples** in §§2.1–2.4 (pp.1–4). Chat example omits both optional history mechanisms because they are not configured, as allowed by §§2.1 and 4; it does not pretend state tokens are supported.

### PR #40 Brain review corrections (2026-11-23; pending focused WSL tests)

- In document-grounded chat and document-based summarization, numbers in the officer's question/instructions **do not** count as cited source evidence; only validated source quotes do. Officer-supplied numeric drafting instructions and text-only summarization source text remain permitted under §§2.2 and 2.4. This is a bounded numeric safeguard, **not** semantic validation of narratives or officer approval.
- Non-null boolean extraction fields are deliberately rejected (502), including `approved: true` supported only by `Approved: not true`. A literal `true`/`false` token does not establish an unnegated proposition. Optional booleans may be `null`, but mandatory booleans are not currently usable. A safe field-specific boolean validator needs separate onboarding and tests (§§2.3, 6.2).
- Representative offline 2–4-document ASCII mock envelopes are **584/759/934 bytes** (narrative) and **483/697/911 bytes** (extraction) against the current **1,600/1,400** output-token requests. Counts are serialized UTF-8 bytes, not actual Qwen tokenizer counts or measured inference. The existing maximum **16 × 512 = 8,192 bytes of quotes** alone does not fit predictably; model prompt requests shorter distinct excerpts without truncation. Detailed evidence/limits and WSL instructions: [EOFFICE_GROUNDING.md](EOFFICE_GROUNDING.md).
